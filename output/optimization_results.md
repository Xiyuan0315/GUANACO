# GUANACO 性能优化实测

2026-09-06。本地对照提交：`447813f`；新版：当前工作区。本报告只覆盖基因读取、marker violin 回调及 dot plot / ATAC 汇总，不代表整个应用的加速倍数。

## 测试条件

- macOS arm64，Python 3.12；NumPy 1.26.4、pandas 2.3.3、SciPy 1.13.1、AnnData 0.12.16。
- dot plot / ATAC：同一份合成数据，200,000 个细胞、80 个特征、20 组、1% 非零值，float32。分别以 CSC、CSR 和密集数组存储。
- 每次清空相关缓存，运行五次取耗时中位数。最终测速未同时运行测试套件。
- dot plot 测完整 `plot_dot_matrix` 调用；ATAC 测 `compute_atac_signal`，不含 ATAC 图形构建。两者均不含浏览器绘制、网络传输、启动及数据集载入时间。
- 内存另行测量，为调用期间 tracemalloc 跟踪到的峰值分配，含新产生的缓存；不含预先载入的数据矩阵、导入及预建索引，**不是整个进程的 RSS**。单位 MiB。

## 结果

| 场景 | 旧版耗时 ms | 新版耗时 ms | 加速倍数 | 旧版峰值 MiB | 新版峰值 MiB |
|---|---:|---:|---:|---:|---:|
| CSC dot plot | 265.13 | 61.15 | 4.34× | 252.49 | 9.12 |
| CSR dot plot | 507.90 | 85.42 | 5.95× | 252.48 | 9.12 |
| CSC ATAC mean | 194.02 | 34.82 | 5.57× | 183.14 | 17.84 |
| CSR ATAC mean | 291.25 | 63.43 | 4.59× | 183.14 | 17.84 |
| 密集 dot plot | 397.55 | 277.32 | 1.43× | 252.47 | 19.34 |
| 密集 ATAC mean | 285.22 | 181.09 | 1.58× | 183.14 | 85.81 |

在上述稀疏场景中，dot plot 的峰值分配减少约 96.4%，ATAC 减少约 90.3%。密集数据仍使用分块汇总；不是将密集矩阵全部转换成稀疏矩阵。

### 基因读取：消除超出缓存容量后的重复读取

另用 1,000,000 个细胞 × 24 个基因、1% 非零 CSC 数据，逐列消费而不保留完整输出，模拟流式 heatmap 的读取方式。

| 指标 | 旧版 | 新版 |
|---|---:|---:|
| 中位耗时 | 56.62 ms | 43.56 ms |
| 峰值分配 | 156.61 MiB | 68.88 MiB |
| 列读取总量 | 48 列 | 24 列 |
| 读取调用数 | 25 | 24 |

旧版先批量读取 24 列，超过 64 MiB 缓存容量后，顺序消费导致后续缓存不断被驱逐，又读取了 24 列。新版分批读取后直接消费，消除了这部分重复工作。这里的“列读取”是矩阵提取计数，不是远程 HTTP 请求数；该实验没有测云端延迟。

### Violin：删除历史图形的浏览器往返

使用 10,000 个细胞、8 个基因、20 组生成同一幅真实 violin figure，按旧回调的数据流序列化图形载荷。在历史图形由 8 幅增加到 9 幅的一次更新中：

- 旧版图形相关 JSON 总量约 **8.10 MiB**；新版约 **0.30 MiB**，减少 **96.3%**。
- 旧版统计包括：上传旧缓存、下载更新后的缓存、再次上传缓存给展示回调、下载当前图形。上一轮已删除的完整 figure State 不计入旧版，以免重复计算收益。
- 新版只需一次渲染回调，直接返回当前图形；未变的请求通过 rendered key 跳过。
- 这是未压缩的图形 JSON 字节对比，不是实测网络流量或端到端延迟；不含通用回调元数据、其他选择状态、HTTP 压缩。

## 有效改动与删除

1. 用分批读取后直接消费替换“全部预热，再逐列从缓存取出”，复用于 heatmap、violin、pseudotime 和多组学数据组装。
2. dot plot / ATAC 共用一个 108 行的汇总模块：稀疏输入直接统计存储值，密集和非有限值输入分块处理；ATAC 只计算用户请求的 mean 或 detection，不再两者都算。
3. 删除整块 ATAC 密集区域缓存及其重复汇总辅助函数；保留可复用的 peak 列缓存，稀疏输入保持稀疏，并加入 64 MiB 数组字节上限。
4. 删除 violin 历史 figure Store、缓存维护函数和单独的展示回调。没有引入新的历史 figure 缓存。
5. 修正 heatmap 在读取过程中 binned cache 淘汰未来命中项的问题；修正 ATAC 修改 track 顺序时误命中旧排序缓存的问题。
6. 保留磁盘/延迟加载 dot plot 的基因缓存复用；修改配色不重新读取已缓存的列。保留现有绘图接口，没有新增第三方依赖或 C++ 编译步骤。

相对对照提交，本批涉及的九个既有生产文件共新增 213 行、删除 268 行；加上 108 行共享模块，净增 **53 行**。此统计不含测试、基准报告、其他工作区改动或上一轮独立的 comparative violin 统计缓存修改。

## 验证与限制

- 389 项测试通过（分两组运行：346 + 43）；另有两项旧 Zarr 元数据类型断言失败。用 `447813f` 的 loader 代码复现了完全相同的失败，未顺手扩大到修改 loader。
- 新增检查覆盖 CSR/CSC/密集矩阵、稀疏重复项、显式零、负值、NaN/Inf、筛选行、layer/raw、磁盘视图、Dask、缓存淘汰和回调去重。
- 基准脚本同时比较旧/新 dot plot 的三种 transformation × 四种 standardization，在密集/稀疏输入上的数值等价性；结果在浮点容差内一致。
- Ruff 与 `git diff --check` 通过。
- 跨所有基因进行百分位裁剪的 z-score transformation 保留原有密集计算定义；不以分块百分位代替全局百分位。它不应套用上述普通汇总路径的提速倍数。
- 8 MiB 是读取批次的目标预算，至少读取一列，不是整个进程的内存硬上限；现有输出、缓存和大型单列仍需内存。
- 尚未在真实远程存储、浏览器端或真实项目数据集上测端到端耗时；不能将这些数字用于声称所有百万细胞交互都同比提速。

## 复现

在项目根目录运行：

```sh
.pixi/envs/default/bin/python output/optimization_benchmark.py
.pixi/envs/default/bin/python -m pytest -o addopts='' -q --ignore=tests/test_loader.py
.pixi/envs/default/bin/python -m pytest -o addopts='' -q tests/test_loader.py -k 'not test_backed_csc_zarr_keeps_x_lazy and not test_backed_csr_zarr_loads'
```

基准脚本只读取 Git 中的旧源码到独立模块，不覆盖工作区源码。
